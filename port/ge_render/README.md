# ge_render: the renderer library

The backends (deko3d on the Switch, Vulkan, OpenGL), the combiner -> shader generator, the shader packs, the window and the
static-mesh API, as one CMake library (`ge_render`, a static library linked by the game and by the tools). It knows no game
and no N64 code: `port/fast3d` translates the N64 display lists into its draw API, the tools draw through the same calls.
Issue #142 (phase 1: #143). Public API: `include/ge_render.h`. The MIT license of the fast3d lineage covers the backends
(`LICENSE.txt`); `include/glad/` is generated by [glad](https://github.com/Dav1dde/glad) (MIT), `src/volk/` is
[volk](https://github.com/zeux/volk) (MIT).

## Layout

| Path | Role |
|---|---|
| `include/ge_render.h` | the API: open/close, poll events, begin/end frame, present, draw vtable, passes, debug draw |
| `include/ge_render_cfg.h` | the config struct (`ge_render_cfg`), no `<stdbool.h>` so the game's C files can include it |
| `include/gfx_rendering_api.h`, `gfx_window_manager_api.h` | the two vtables (N64 vocabulary: combiner ids, RDP blend/depth modes, clamp/mirror) |
| `include/gfx_cc.h`, `src/gfx_cc.cpp` | combiner id -> features (the shader generators and `tools_pc/dkshgen` use it) |
| `include/ge_render_sky.h` | `PortSkyPlus`, the GE+ sky/sea/water pass descriptor |
| `include/ge_render_gl.h` | GL extras for a host that draws raw GL on the context (the game's first-launch GPU benchmark) |
| `include/glad/` | the GL loader |
| `src/ge_render.cpp` | `ge_render_open`: backend choice, the window per backend, the frame calls |
| `src/ge_core.cpp` | config, host callbacks and their defaults, `ge_render_cc_id` (no backend: the editor links it alone with `gfx_opengl.cpp`) |
| `src/ge_window_sdl.cpp` | the SDL window: GL context, Vulkan window, or no window (deko3d); the event pump |
| `src/gfx_opengl.cpp`, `gfx_vulkan.cpp`, `gfx_deko3d.cpp` | the backends |
| `src/gfx_dk_*.h`, `gfx_vk_pack.S`, `gfx_dk_pack.S` | the shader pack format and the `.incbin` of the packs `cmake/` builds from `port/shaders/` |
| `src/ge_debugdraw.cpp` | `ge_debug_*`: lines and points through `draw_triangles` |

## Rules

- Nothing here calls the game. What it needs comes in through `GeRenderCallbacks` (log, fatal, arguments, paths, sleep,
  handheld/console, and the events: quit, keys, mouse, text, pads, audio device, resize, focus, dock) and `ge_render_cfg`
  (fxaa, fog form, display fixes, sky scale; the backends write `rdp_affine`, `fog_vertex`, `skyplus_*`, `water_surfaces`).
- `ge_render_open` creates the backend's own window or surface and runs the backend's init. The host owns the loop and its
  threads: the game binds the context on its render thread (`ge_render_bind_thread`) and parks it at quit (`ge_render_park`).
- It still reads `<PR/gbi.h>` for the RDP constants (G_TX_*, blend and depth modes).

## The hello host

`tools_pc/ge_render_hello` is the smallest host: it opens a window on the chosen backend and draws a backdrop and a few
debug lines through `ge_render.h` only. Off by default: configure with `-DGE_TOOLS=ON`.

```sh
cmake -S . -B build-linux -G Ninja -DROMID=ntsc-final -DGE_TOOLS=ON && cmake --build build-linux   # inside the build image
build-linux/tools_pc/ge_render_hello/ge_render_hello --backend gl|vk --frames 120 --dump hello.ppm
```

On the Switch the same target is `ge_render_hello.nro` (deko3d, 600 frames, then it exits).
